# Фоновые задания хостинга

Статус: реализовано и проверено на двух нодах и в production. Обновлено: 17.11.2026, 15:32 UTC.

Документ фиксирует карту изменений, контракт и поэтапный план. Он же служит журналом:
после каждого этапа здесь обновляется статус и проверки.

| Компонент | Файл | Решение |

| API | `server/src/routes/hosting-jobs.ts` | Список и ручная постановка задания владельцем |

Отдельную таблицу и отдельный worker-процесс не создаём: это дублировало бы аренду, повторы и
дедупликацию. Фоновые задания получают **отдельный пул** внутри того же worker-кода, чтобы
архивация проекта не блокировала оплату и webhook'и.

## 2. Контракт

`nestdev.functions.json` расширяется необязательным массивом `jobs`:

```json
{
  "version": 1,
  "runtime": "node",
  "functions": [
    {
      "name": "checkout",
      "path": "/api/checkout",
      "methods": ["POST"],
      "handler": "functions/checkout.ts#handler"
    }
  ],
  "jobs": [
    {
      "name": "send-receipt",
      "handler": "functions/jobs/send-receipt.ts#handler",
      "timeoutMs": 60000,
      "memoryMb": 256
    }
  ]
}
```

Правила:

- имя задания уникально среди функций и заданий;
- `handler` — путь внутри проекта и имя экспорта;
- `timeoutMs` — 100..60000, по умолчанию 30000;
- `memoryMb` — 128..512, по умолчанию 256;
- максимум 10 заданий;
- задание не имеет HTTP-маршрута и не принимает внешние запросы напрямую.

### Постановка из функции

HTTP-обработчик может вернуть вместе с ответом список заданий:

```ts
return {
  status: 202,
  body: { accepted: true },
  jobs: [
    {
      name: "send-receipt",
      idempotencyKey: "order:" + order.id,
      payload: { orderId: order.id }
    }
  ]
};
```

Платформа ставит задания в очередь **до отправки ответа**. Если постановка не удалась, клиент
получает ошибку, а не ложное `202`. `idempotencyKey` необязателен; с ним повторный вызов не
создаст второе задание, пока первое активно. Без ключа создаётся новое задание.

Ограничения: до 10 заданий в одном ответе, payload до 64 КиБ, не более 100 активных заданий
на проект.

### Выполнение

Задание запускается тем же одноразовым контейнером, что и функция:

- артефакт монтируется read-only;
- сеть `bridge`, без доступа к PostgreSQL и внутренней сети платформы;
- `cap-drop ALL`, `no-new-privileges`, non-root, read-only rootfs;
- лимиты 0.5 CPU, 256 МБ по умолчанию, до 512 МБ;
- таймаут до 60 секунд;
- ответ до 2 МиБ, но в БД пишется только краткий итог, не тело.

Обработчик задания получает тот же объект, что и HTTP-функция:

```ts
{ method: "JOB", path: "/__job__", query: "", headers: {}, body: Buffer }
```

`body` — JSON payload задания. Задание не должно слушать порт, хранить состояние между
запусками или писать в каталог проекта.

## 3. Тарифы и лимиты

| Возможность | Старт | Плюс | Премиум |
|---|---:|---:|---:|
| Статика | да | да | да |
| HTTP-функции | нет | да | да |
| Фоновые задания | нет | нет | да |

Причины:

- «Плюс» остаётся дешёвым: статика, оплата, доставка и короткие webhook'и;
- фоновые задания добавляют очередь, worker-слоты, повторы и мониторинг — это «Премиум»;
- тяжёлые задачи (видео, OCR, puppeteer) не входят ни в один тариф: они требуют отдельной ВМ.

Настройки:

- `BACKGROUND_JOBS_ENABLED=1` — включить пул;
- `BACKGROUND_JOBS_CONCURRENCY=2` — два слота на ноду;
- `BACKGROUND_JOBS_MAX_ACTIVE=100` — активных заданий на проект.

## 4. Карта изменений

1. `server/src/functions/manifest.ts` — схема `jobs`, проверка дублей.
2. `server/src/functions/build.ts` — сборка заданий в `.functions/<name>`.
3. `server/src/functions/invoke.ts` + `worker.mjs` — `jobs` в ответе, лимит 60 секунд.
4. `server/src/storage/function-jobs-table.ts` — миграция колонок.
5. `server/src/jobs/store.ts` — поля задания, приоритет, фильтр видов, результат.
6. `server/src/jobs/worker.ts` — `kinds` в `startJobWorker`.
7. `server/src/hosting/background-jobs.ts` — валидация и постановка.
8. `server/src/hosting/background-jobs-run.ts` — выполнение задания.
9. `server/src/hosting/publisher.ts` — тарифный gate при публикации.
10. `server/src/functions/host-server.ts` — постановка после HTTP-ответа.
11. `server/src/routes/hosting-jobs.ts` — API владельца.
12. `server/src/index.ts` — отдельный пул фоновых заданий.
13. `docker-compose.yml`, `deploy/node*/docker-compose.override.yml` — env.
14. Тесты рядом с модулями, документация тарифов.

## 6. Что не входит

- cron/расписание (следующий этап, после стабильной очереди);
- произвольные очереди пользователя;
- видео, ffmpeg, OCR, puppeteer;
- отдельная worker-ВМ;
- биллинг за миллисекунды.
