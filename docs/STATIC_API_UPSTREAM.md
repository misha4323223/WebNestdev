# Внешний API у статического проекта

Статический предпросмотр отдаёт файлы с того же origin, что и панель
(`<проект>.preview.nestdev.ru` и `/api/projects/<id>/preview/open/`). Если API проекта
живёт на другом домене, браузер применяет CORS: ответ `Access-Control-Allow-Origin: *`
не подходит для `credentials: include`, а API без `OPTIONS` не проходит preflight.

Поэтому платформа даёт статическому проекту **same-origin прокси**:

```json
{
  "preview": {
    "apiUpstream": "https://api.example.com/api"
  }
}
```

Правила контракта:

- только публичный HTTPS-адрес;
- без логина, пароля, query и fragment;
- путь — база API, например `/api`; он сохраняется при проксировании;
- локальные и приватные адреса запрещены, имя проверяется по DNS при каждом запросе;
- клиент ходит на относительный `/api/upstream/...`, а не на чужой origin.

Например:

```ts
const api = axios.create({
  baseURL: "/api/upstream",
  withCredentials: true,
});
```

Платформа пересылает метод, query, тело, `Authorization` и cookies, а `Set-Cookie`
переписывает на домен предпросмотра. Это работает и без контейнера: прокси живёт в
listener'е статического предпросмотра.

## Когда контракт не нужен

- API уже на том же origin (`/api`).
- У проекта есть собственный сервер: для него используется hybrid или контейнерный
  предпросмотр, а `/api` уходит в серверную часть.
- Нужны WebSocket/SSE, SSR или долгие соединения — статический предпросмотр и этот
  прокси их не заменяют, нужен серверный runtime.

## Ограничения

Прокси не является открытым сетевым прокси: адрес фиксирован в проекте, а не
приходит из браузера. Есть лимит тела запроса и таймаут, поэтому большие загрузки и
долгие ответы нужно отдавать через серверный runtime.
