Статус: план выполнен в октябре 2026 — в каталоге только российские провайдеры; зарубежные
оставлены на следующий этап. Документ основан на аудите кода (`IntegrationsList`, `cloud/`,
`domains/`, `services/`, `database-connection-store.ts`, `auth/sms.ts`), каталоге коннекторов
Replit и доступности российских API. Ниже — что уже в коде и что осталось.

## 2. Три уровня интеграции (разная стоимость)

1. **Секрет + текст (дёшево).** Пользователь вставляет ключ через `secrets.request`, агент пишет код
   под провайдера. Нового серверного кода не нужно — нужны только знание провайдеров и подсказки
   в системном промпте. Годится для платежей, email, SMS, карт, аналитики по ключу.
2. **Коннектор с проверкой ключа (средне).** Карточка как у облаков: проверка ключа до сохранения,
   хранение зашифрованным, инструмент агента для чтения. Полезно там, где агент может использовать
   ключ сам (хранилище файлов, аналитика, AI пользователя).
3. **OAuth-подключение (дорого).** Кнопка «Войти и разрешить»: нужна регистрация нашего приложения
   у провайдера и поддержка redirect/polling. Оправдано только для сервисов, где API-ключ
   пользователю выдать негде (Метрика, AppMetrica, amoCRM, Bitrix24).

## 3. Приоритеты

### P0 — деньги платформы (Фаза 3 MASS_ADOPTION_PLAN)

В каталоге: ЮKassa, Robokassa, Т-Банк, CloudPayments. Merchant-схема (платёжный модуль самой
платформы) — отдельная работа, карточки закрывают только приложения пользователей.

| Сервис | Зачем | Как подключается | Риски |
|---|---|---|---|
| **ЮKassa** | Оплата подписок, самая известная в РФ | Merchant-креденшелы магазина (`shopId`, `secretKey`), API + webhooks | Поддержка чеков/выплат для самозанятых прекращена 29.12.2025 — уточнить актуальную схему |
| **Robokassa** | Альтернатива с явным приёмом самозанятых | Идентификатор магазина + пароли, API и платёжные ссылки | Модерация и верификация бизнеса |
| **Т-Банк (T-Касса)** | Приём карт, ссылки, подписки | Терминальные креденшелы банка | Ориентировано на ИП/ООО |
| **CloudPayments** | Рекуррентные платежи | Public ID + API Secret | Юрформа не подтверждена документацией |

Решение по конкретному провайдеру — отдельный шаг при входе в фазу монетизации; для самой платформы
это не коннектор в UI, а серверный платёжный модуль.

### P1 — то, что чаще всего нужно в сгенерированных приложениях

Сделано: S3 (5 провайдеров), почта (NotiSend, Sendsay, RuSender, Unisender, Yandex Cloud Postbox), AI (GigaChat,
Yandex AI Studio). Не сделано: Yandex Metrika — нужен OAuth-вход, отдельный этап.

| Сервис | Зачем | Как подключается | Примечание |
|---|---|---|---|
| **S3-хранилище: Selectel / VK Cloud / Yandex Object Storage / Timeweb** | Загрузка файлов, аватары, документы — самая частая просьба | Access Key + Secret Key (у Yandex — статический ключ сервисного аккаунта); проверка ключа листингом бакетов | Один общий коннектор «Файлы (S3)» с выбором провайдера; данные остаются у пользователя |
| **Unisender / Sendsay** | Письма из приложения: подтверждения, сброс пароля, уведомления | API-ключ из кабинета; проверка запросом к аккаунту | Пользовательские карточки — для писем из сгенерированных приложений; собственные письма платформы уже идут через Postbox (`docs/MAIL.md`), сброс пароля по email ещё не сделан |
| **GigaChat (Sber) / Yandex AI Studio** | AI внутри приложения пользователя | Client ID + Secret (GigaChat, обмен на токен) или API-ключ (Yandex); у GigaChat есть тарифы для физлиц | Даёт «AI-приложение без зарубежной карты» — сильное отличие от Replit/Lovable |
| **Yandex Metrika** | Аналитика сайта пользователя | OAuth-подключение к счётчику (у Метрики это единственный нормальный путь) | После подключения агент сам вставляет код счётчика — заметная «магия» |

### P2 — расширение каталога

Сделано: карты (Yandex Maps, 2GIS), CRM (RetailCRM, Битрикс24 через входящий вебхук, amoCRM).
Для amoCRM и Битрикс24 выбран путь без OAuth — вебхук и токен из кабинета: OAuth-приложение
платформы требует регистрации у каждого провайдера, а ключ пользователь выдаёт сам за минуту.

Не сделано (нет безопасного self-service API или нужен OAuth платформы):

| Сервис | Почему отложено |
|---|---|
| **Yandex Metrika / AppMetrica** | Только OAuth-подключение к счётчику; нужен этап с регистрацией приложения |
| **Yandex Cloud Notification Service / RuStore** | Push относится к мобильным сборкам, которых у платформы пока нет |
| **GlitchTip (self-host)** | Не российский (США/ЕС); решение — только self-host, отдельная инфраструктура |
| **Yandex Message Queue** | Очереди нужны редко; инструменты агента уже позволяют работать с SQS-совместимым API по ключу |

### P3 — по мере спроса

CRM-агенты и поддержка (Jivo), видео (встраивание VK Video/Rutube без загрузки),
CDN (Yandex Cloud CDN, Selectel), вебхуки и автоматизации, CMS (1С-Битрикс, WordPress через API).

## 4. Чего не обещать

Проверено по документации — публичного self-service API нет или доступ не подтверждён:
прямой SMS у Beeline и MegaFon, MailoPost, публичный inference MTS Cotype и T-Bank T-Pro,
загрузка видео в Rutube и публикация в VK Video, managed realtime в РФ (ближайшее — свой
WebSocket/Socket.IO на инфраструктуре пользователя). Появляться в каталоге им нельзя, пока
провайдер не опубликует API.

## 6. Юрисдикция провайдеров

Проверено в октябре 2026 — важно для продуктового обещания «российские сервисы». Весь каталог
`services/` проходит по этому списку; зарубежных карточек в нём нет.

- **Файлы (S3)**: Selectel, VK Cloud, Yandex Object Storage, Timeweb, Cloud.ru — все российские. Сам протокол S3 придуман Amazon, но это формат, а не провайдер; при желании тот же код работает и с зарубежным хранилищем пользователя.
- **Почта**: NotiSend — российский, серверы в РФ; Sendsay — позиционирует себя полностью российским; RuSender — российский; Yandex Cloud Postbox — сервис Яндекса в Yandex Cloud; **Unisender** работает в РФ и самый известный, но его лицензиар зарегистрирован на Кипре — в интерфейсе это стоит указывать честно.
- **Оплата**: ЮKassa (Сбер), Robokassa (принимает самозанятых), Т-Банк, CloudPayments (100% у Т-Банка) — все российские.
- **AI**: GigaChat (Сбер) и Yandex AI Studio — российские. Отдельно: собственный агент платформы сейчас работает через зарубежный OpenAI-совместимый роутер (`ai-proxy/`, `PLATFORM_AI_*`) — это про ключ владельца, а не про интеграции пользователей.
- **Карты**: Yandex Maps, 2GIS — российские.
- **CRM**: RetailCRM, amoCRM, Bitrix24 — российские.
- **Мониторинг ошибок**: единственный не российский пункт — Sentry/GlitchTip (США/ЕС). Российского аналога с открытым API нет, поэтому вывод — self-host у себя, тогда данные остаются на нашей стороне. Обещать «российский мониторинг» нельзя.
- **SMS**: уже подключённые SMS.RU, SMSC, Exolve, SMS Aero, Yandex Notify — российские.

## 7. Что осталось

1. **Почта самой платформы** — подключена: оплата, предупреждение о списании и обращения
   поддержки уходят через Yandex Cloud Postbox (ключи — группа «Почта (Yandex Cloud Postbox)»,
   шаги — `docs/MAIL.md`). Остались подтверждение адреса и сброс пароля по почте: сегодня
   единственный канал входа — SMS.
2. **Yandex Metrika** — единственная крупная категория, которой нужен OAuth-вход.
3. **Платёжный модуль платформы** — сделан на Робокассе: счёт, `ResultURL`, подписка, история
   платежей, автопродление, письмо об оплате и предупреждение о списании (`docs/ROBOKASSA.md`,
   `docs/MAIL.md`). Остались возвраты из интерфейса и счета/акты для юрлиц.
4. **Зарубежные провайдеры** (Stripe, Resend, SendGrid, OpenAI, Google Maps, HubSpot) — следующий
   этап, после российского набора. Схема карточки та же: `catalog.ts` + `verify.ts` + каталог панели.
