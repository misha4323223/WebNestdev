# Платформенный доступ к AI-модели

NestDev умеет работать без настройки провайдера в каждом проекте: если у проекта нет
своего провайдера, агент использует модель платформы из переменных окружения. Свой
провайдер в настройках проекта остаётся опцией и всегда имеет приоритет.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `PLATFORM_AI_BASE_URL` | OpenAI-совместимый Base URL, например `https://api.example.com/v1` |
| `PLATFORM_AI_API_KEY` | Ключ провайдера; хранится только на сервере и не отдаётся клиенту |
| `PLATFORM_AI_MODEL` | Идентификатор модели по умолчанию |
| `PLATFORM_AI_PROVIDER` | Отображаемое имя (по умолчанию «Платформа NestDev») |
| `PLATFORM_AI_PRICE_INPUT_PER_MILLION` | Цена за 1M входных токенов (для оценки расходов) |
| `PLATFORM_AI_PRICE_OUTPUT_PER_MILLION` | Цена за 1M выходных токенов (для оценки расходов) |
| `PLATFORM_AI_PRICE_CURRENCY` | Валюта оценки, по умолчанию `USD` |
| `PLATFORM_AI_MODEL_PRICES` | Цены по моделям для админской статистики: JSON `{"<часть имени>":{"input":…,"output":…}}` за 1M токенов. Если задана, точнее общей ставки |
| `PLATFORM_AI_CREDITS_INPUT_PER_MILLION` | Кредитов за 1M входных токенов основной модели; по умолчанию 50 |
| `PLATFORM_AI_CREDITS_OUTPUT_PER_MILLION` | Кредитов за 1M выходных токенов основной модели; по умолчанию 510 |
| `PLATFORM_AI_CREDITS_MINIMUM_PER_RUN` | Минимум кредитов за запуск основной модели; по умолчанию 1 |
| `WEBNESTDEV_AI_REASONING` | Просить ли у модели цепочку рассуждений: `medium` (по умолчанию), `low`, `high` или `off`. Работает и для модели платформы, и для провайдера проекта |

Три ставки `PLATFORM_AI_CREDITS_*` можно сохранить и через API админ-приложения
(`POST /api/admin/ai`, поле `creditRates`); значение из админки важнее окружения.

Прежние имена `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`, `AI_PROVIDER` продолжают работать
как алиасы.

Генерация изображений для проектов — это отдельный набор `PLATFORM_IMAGE_*` и отдельный инструмент
агента `image.generate`, а не ещё одна модель: см. «Генерация изображений для проектов» ниже.
Включение картинок не меняет ни бесплатную модель тарифа, ни платную модель платформы. Примеры окружения (`.env.example`) управляются платформой отдельно; значения
добавляются через Settings → Environment (для деплоя) или `.env.local` (для локального
запуска).

## Бесплатный тариф: Agnes AI или Cloudflare Workers AI с резервом на платформу

На тарифе «Старт» проект без своего AI-провайдера работает не на платной модели платформы, а на
бесплатной — по умолчанию Agnes AI, но адрес можно заменить на любой OpenAI-совместимый
(например, Cloudflare Workers AI). Платные тарифы это не затрагивает: у них по-прежнему основной
`PLATFORM_AI_*`, а бесплатная цепочка используется только при `plan === "free"` и только когда у
проекта нет своего провайдера.

| Переменная | Назначение |
| --- | --- |
| `PLATFORM_AI_FREE_BASE_URL` | OpenAI-совместимый адрес бесплатной модели, например `https://apihub.agnes-ai.com/v1` |
| `PLATFORM_AI_FREE_MODEL` | Идентификатор модели, например `agnes-2.5-flash` или `@cf/openai/gpt-oss-120b` |
| `PLATFORM_AI_FREE_PROVIDER` | Необязательное имя провайдера для логов и подписей; по умолчанию `Agnes AI` |
| `PLATFORM_AI_FREE_KEY_1` | Ключ первого аккаунта — основной |
| `PLATFORM_AI_FREE_KEY_2` | Ключ второго аккаунта — первый резерв |
| `PLATFORM_AI_FREE_KEY_3` | Ключ третьего аккаунта — второй резерв |

Резервом служит платная модель из `PLATFORM_AI_*` (для этого проекта — Yandex Cloud AI Studio).
Если бесплатная конфигурация не задана целиком, бесплатный тариф работает ровно как раньше, на
модели платформы: незаполненные переменные ничего не ломают.

Как ведёт себя шаг:

- начинает с последнего ключа, который ответил; успешный ключ запоминается на процесс;
- `401/403` — ключ в паузе 10 минут, шаг идёт к следующему;
- `429` — пауза по `Retry-After` (не меньше 5 секунд, иначе 60 секунд), шаг идёт к следующему;
- `5xx` и сетевой обрыв — короткая пауза 30 секунд, шаг идёт к следующему;
- `400` (например, модель не принимает инструменты) — ключ в паузе 5 минут, шаг идёт к следующему;
  отказ по размеру контекста и по числу сообщений сюда не входит — там история сокращается, а не
  меняется ключ;
- если ответ уже начал приходить, переключения нет: пользователь видит часть ответа и кнопку
  «Продолжить», иначе текст пришёл бы дважды;
- когда все бесплатные ключи в паузе, шаг ждёт ближайшего освобождения; резерв не становится
  основным и после паузы бесплатные ключи снова первые.

Ключи удобно передавать через GitHub Actions: `PLATFORM_AI_FREE_BASE_URL`,
`PLATFORM_AI_FREE_MODEL` и `PLATFORM_AI_FREE_PROVIDER` — в Variables, `PLATFORM_AI_FREE_KEY_1..3` —
в Secrets. Выкатка пробрасывает их в `.env` на ВМ; пустые значения ничего не стирают. Те же
значения можно задать в панели «Ключи сервера» — они читаются без перезапуска.

На бесплатном тарифе плашка у поля ввода называется **NestDev Air** и несёт бейдж **Free**:
конкретное имя провайдера не показывается, потому что ответ может прийти и от резерва, но
человеку нужен понятный вход в линейку. Учёт токенов при этом ведётся, а в журнале расхода такие
запуски помечены как `free-model`.

## Дополнительные модели платформы: Max и Mini

Платная основная модель называется **NestDev** и по-прежнему задаётся `PLATFORM_AI_*`. Две
дополнительные модели — **NestDev Max** (сложные задачи) и **NestDev Mini** (экономичные
итерации) — не хранятся в переменных окружения. Их добавляет администратор через API внешней
админки, и они появляются у платных тарифов без выкатки и перезапуска:

- `GET /api/admin/ai/models` — список моделей и их состояние;
- `PUT /api/admin/ai/models/:id` — добавить или обновить (например, `max` или `mini`);
- `PATCH /api/admin/ai/models/:id` — изменить название, тарифы или контекст;
- `POST /api/admin/ai/models/test` — проверить адрес, модель и ключ настоящим вызовом;
- `DELETE /api/admin/ai/models/:id` — убрать модель.

Адрес, модель и ключ у каждой свои — подойдёт любой OpenAI-совместимый провайдер или агрегатор.
Ключи лежат в зашифрованном `platform/models.json` и никогда не возвращаются в ответе. Полное
описание и примеры — [ADMIN_API.md](ADMIN_API.md), раздел 7.13.

Клиент присылает в запуск `model`: `nestdev` для основной, `nestdev-air` для бесплатной или id
модели из каталога. Сервер сам проверяет, что модель включена и разрешена тарифу; подставить
upstream-имя в обход каталога нельзя. Без выбора платный тариф работает на `NestDev`.

## Генерация изображений для проектов (`image.generate`)

Агенту нужны не только слова: сайту, магазину или лендингу нужны настоящие фотографии и
иллюстрации. Для этого в наборе инструментов есть **`image.generate`** — он рисует картинку по
текстовому описанию и кладёт её файлом в проект, откуда её подключают в код как любой другой
ассет. Это не модель агента и не второй провайдер разговора: разговор по-прежнему идёт на Agnes и
на модели платформы, а картинки уходят отдельным запросом в сервис изображений.

| Переменная | Назначение |
| --- | --- |
| `PLATFORM_IMAGE_BASE_URL` | Адрес сервиса изображений. Cloudflare Workers AI: `https://api.cloudflare.com/client/v4/accounts/<Account ID>/ai/run` — имя модели дописывается к адресу; OpenAI-совместимый сервис: адрес с `/v1`, к нему допишется `/images/generations` |
| `PLATFORM_IMAGE_MODEL` | Чем рисовать: `@cf/black-forest-labs/flux-1-schnell` (быстро, до 8 шагов) или `@cf/stabilityai/stable-diffusion-xl-base-1.0` (принимает размер и негативный промпт) |
| `PLATFORM_IMAGE_PROVIDER` | Необязательно: имя сервиса в логах и подсказках, по умолчанию `Cloudflare Workers AI` |
| `PLATFORM_IMAGE_KEY_1` | API-токен сервиса; у Cloudflare — с правом `Workers AI: Read` |
| `PLATFORM_IMAGE_KEY_2` / `PLATFORM_IMAGE_KEY_3` | Необязательно: ключи других аккаунтов — запрос идёт к ним, когда первый упирается в лимит или отклонён |

Имена свои, в стороне от `PLATFORM_AI_*` и `PLATFORM_AI_FREE_*`: включение картинок не меняет ни
бесплатную модель тарифа, ни платную модель платформы. Незаданные переменные ничего не ломают —
инструмент отвечает агенту «не настроено» и называет, чего не хватает, а агент передаёт это
пользователю вместо выдуманной картинки.

Что делает инструмент:

- `prompt` — описание кадра (сюжет, стиль, ракурс, свет); `size` — `1024x1024` для моделей, которые
  его принимают; `negativePrompt` — что не должно появиться;
- без `path` файл ложится в `public/images/<имя по описанию>.<расширение>`, и существующий файл не
  перезаписывается: второе «нарисуй кота» не затирает первое. С `path` заменяется именно этот
  ассет, а расширение приводится к настоящему формату ответа (`.png`, `.jpg`, `.webp`);
- `show: true` — когда пользователь просит нарисовать картинку, чтобы посмотреть на неё: готовая
  картинка появляется в чате под ответом и открывается в полном размере, а сама модель её в ответ
  не вставляет. Без этого флага (картинка нужна самому проекту) в переписке ничего не показывается —
  файл просто лежит в проекте;
- картинку проекта видно и вне чата: в панели «Файлы» она открывается как изображение, а маршрут
  `GET /api/projects/<id>/asset?path=…` отдаёт только растровые форматы (PNG, JPEG, WebP, GIF,
  AVIF, BMP, ICO — SVG исключён, потому что он исполняет скрипты на домене сервиса);
- пишется только внутрь проекта: `.git` и `.env*` запрещены, как у `net.download`;
- в планировщике запрещён: это запись в проект и расход ключа платформы;
- результат виден в логе сервера: `[image] <модель> -> <файл> bytes=… project=…`. Описание и ключ
  в журнал не попадают.

### Токен и модель Cloudflare Workers AI

1. Панель Cloudflare → **Workers & Pages** → скопируйте **Account ID** (это не секрет, он входит в
   адрес).
2. **My Profile → API Tokens → Create Token**, право **Workers AI: Read** — для запуска моделей
   его достаточно. Токен хранится только в Secrets или в панели «Ключи сервера», но не в
   репозитории.
3. Задайте переменные:

```dotenv
PLATFORM_IMAGE_BASE_URL=https://api.cloudflare.com/client/v4/accounts/<ACCOUNT_ID>/ai/run
PLATFORM_IMAGE_MODEL=@cf/black-forest-labs/flux-1-schnell
PLATFORM_IMAGE_KEY_1=<API token>
```

В GitHub Actions адрес, модель и имя сервиса — **Variables** (или Secrets), ключ — **только
Secrets**: `PLATFORM_IMAGE_BASE_URL`, `PLATFORM_IMAGE_MODEL`, `PLATFORM_IMAGE_PROVIDER`,
`PLATFORM_IMAGE_KEY_1`. Те же имена есть в панели «Ключи сервера», и значение из панели важнее
окружения: если картинки вводятся там, из GitHub передавать ничего не нужно.

После выкатки смотреть две строки — в логе выкатки и в логе сервера:

```
[deploy] Генерация изображений: адрес=есть, модель=@cf/black-forest-labs/flux-1-schnell, ключ=есть
[image] генерация изображений: Cloudflare Workers AI (@cf/black-forest-labs/flux-1-schnell), ключей 1
```

«PLATFORM_IMAGE_* не заданы» во второй строке означает, что инструмент выключен: агент честно
скажет пользователю, каких переменных не хватает, и не подменит результат заглушкой.

**Лимиты и деньги.** У Cloudflare бесплатно 10 000 Neurons в сутки, сброс в 00:00 UTC; дальше — по
Neurons (на Workers Paid $0.011 за 1 000 Neurons). Цена картинки зависит от модели: у FLUX.1 schnell
она складывается из тайлов 512×512 и шагов, у Stable Diffusion XL в прайсе модели стоит `$0.00 за
шаг`. Несколько картинок за запуск — это заметно дешевле разговора с моделью, но не ноль.

Запрос идёт с сервера платформы тем же защищённым транспортом, что `web.read`: адрес берётся только
из `PLATFORM_IMAGE_BASE_URL` и проверяется (только https, только публичные адреса), а ключ никогда
не является аргументом инструмента — модель не может отправить его на произвольный хост.
**Доступность из РФ.** Российские провайдеры ограничивают соединения к Cloudflare: если запросы
рвутся, инструмент вернёт отказ с причиной, а запуск агента не сломается. Для стабильной работы
выбирайте адрес сервиса, доступный с ВМ.

## Как сменить провайдера из приложения админки

Главный агент настраивается без правки `.env` и перезапуска. Веб-панель для этого не нужна:
приложение админки вызывает API с обычным `Authorization: Bearer <токен>`.

1. `GET /api/admin/ai` — текущий провайдер, Base URL, модель и источник ключа. Значения ключа
   в ответе нет.
2. `POST /api/admin/ai/test` — проверить черновик настоящим вызовом с инструментом. В теле
   `provider`, `baseUrl`, `model` и необязательный `apiKey`; без нового ключа проверка берёт
   сохранённый. Результат содержит `ok`, `latencyMs` и `tools`.
3. `POST /api/admin/ai` — сохранить и сразу включить:

```json
{
  "provider": "OpenRouter",
  "baseUrl": "https://openrouter.ai/api/v1",
  "model": "deepseek/deepseek-chat",
  "apiKey": "sk-or-…"
}
```

`apiKey` необязателен: без него сохраняется текущий ключ — удобно при смене только модели или
адреса у того же провайдера. Новые запуски используют нового провайдера сразу; проекты со своим
AI-провайдером не затрагиваются. Полный контракт, ответы и примеры —
[ADMIN_API.md](ADMIN_API.md), раздел 7.12.

Бесплатная модель тарифа «Старт» (`PLATFORM_AI_FREE_*`) и сервис картинок (`PLATFORM_IMAGE_*`)
настраиваются отдельно ниже и не меняются вместе с главным провайдером. Ставки расхода
(`PLATFORM_AI_PRICE_*`) тоже задаются отдельно в окружении выкладки.

## Как включить через окружение

1. Задайте `PLATFORM_AI_PROVIDER`, `PLATFORM_AI_BASE_URL`, `PLATFORM_AI_API_KEY` и
   `PLATFORM_AI_MODEL` там, где запущен сервер: в Freebuff — Settings → Environment этого
   проекта (значения подхватят терминал и preview); на проде — в окружении сервера
   (ВМ/контейнер). Для теста выкладывать в прод не обязательно.
2. Перезапустите сервер. Проекты без настроенного провайдера сразу используют модель
   платформы, а в настройках проекта появляется подсказка, что работает модель платформы.
3. Чтобы видеть деньги, задайте `PLATFORM_AI_PRICE_*`.
4. Нажмите «Проверить подключение» в настройках AI-провайдера: проверка делает реальный
   пробный вызов с инструментом и показывает, поддержаны ли вызов инструментов (tools)
   и стриминг. Проверяется сохранённая конфигурация (проекта или платформы).

> **Docker:** проверка подключения и учёт токенов работают без Docker. Но полный цикл
> «агент собрал и проверил сайт» требует Docker (песочница и Preview-контейнеры) — на
> машине или ВМ, где Docker доступен.

## Подключение Yandex Cloud AI Studio (пример)

1. В консоли Yandex Cloud создайте каталог (или возьмите существующий) и привяжите
   платёжный аккаунт. Запишите ID каталога вида `b1g...`.
2. В разделе IAM создайте сервисный аккаунт (например `ai-model-user`) с ролью
   `ai.languageModels.user` на каталог.
3. Создайте API-ключ этого сервисного аккаунта со scope `yc.ai.languageModels.execute`
   и сохраните секрет.
4. Задайте переменные окружения:
   - `PLATFORM_AI_BASE_URL=https://ai.api.cloud.yandex.net/v1`
   - `PLATFORM_AI_API_KEY=<секрет API-ключа>`
   - `PLATFORM_AI_MODEL=gpt://<folder-id>/qwen3-235b-a22b-fp8/latest`
     (альтернативы: `gpt://<folder-id>/gpt-oss-120b/latest`, `.../gpt-oss-20b/latest`)
   - `PLATFORM_AI_PROVIDER=Yandex Cloud AI Studio`
5. Цены для оценки расхода (за 1M токенов, вкл. НДС; по прайсу AI Studio на октябрь
   2026 — сверяйте в консоли):
   - Qwen3 235B — `PLATFORM_AI_PRICE_INPUT_PER_MILLION=500`, `PLATFORM_AI_PRICE_OUTPUT_PER_MILLION=500`
   - gpt-oss-120b — `300` и `300`
   - gpt-oss-20b — `100` и `100`
   - `PLATFORM_AI_PRICE_CURRENCY=RUB`
6. Перезапустите сервер и проверьте подключение кнопкой в настройках: агент требует
   поддержки вызова инструментов (tools), поэтому без зелёной проверки создавать
   проекты на этой модели нельзя.

## Подключение DeepSeek через Polza.ai

Polza.ai — OpenAI-совместимый агрегатор, поэтому отдельный клиент для него не нужен: достаточно
`PLATFORM_AI_BASE_URL` с `/api/v1`. Для DeepSeek V4.1 Flash:

| Переменная | Значение |
| --- | --- |
| `PLATFORM_AI_PROVIDER` | `Polza.ai` |
| `PLATFORM_AI_BASE_URL` | `https://polza.ai/api/v1` |
| `PLATFORM_AI_MODEL` | `deepseek/deepseek-v4.1-flash` |
| `PLATFORM_AI_API_KEY` | ключ из кабинета Polza.ai |
| `PLATFORM_AI_MODEL_PRICES` | `{"deepseek/deepseek-v4.1-flash":{"input":1.61,"output":16.41}}` |
| `PLATFORM_AI_PRICE_CURRENCY` | `RUB` |

Цены в примере — по каталогу Polza.ai на 31.10.2026, за 1M токенов; сверяйте их в кабинете перед
выкаткой. Контекст модели — 1M токенов, вызов инструментов поддержан (агенту он обязателен),
поэтому после сохранения ключа обязательно нажмите «Проверить подключение».

Тот же DeepSeek доступен напрямую (`https://api.deepseek.com/v1`, модель `deepseek-flash`) и в
Yandex Cloud AI Studio (`gpt://<folder-id>/deepseek-v4-flash`). Кэширование ниже работает и там,
но `prompt_cache_key` отправляется только на Polza: у прямых API такого поля нет.

## Кэширование контекста

Кэш контекста — это не наш ответный кэш и не сокращение истории. Провайдер сохраняет уже
обработанный префикс промпта и на следующем шаге читает его дешевле; модель при этом видит тот
же текст, что и раньше. Поэтому выигрыш даёт не отдельная кнопка, а стабильный порядок промпта
и корректная разметка для конкретного семейства моделей.

| Семейство | Режим | Что делает платформа |
| --- | --- | --- |
| DeepSeek | Автоматический | Держит префикс стабильным; на Polza отправляет `prompt_cache_key`, чтобы все шаги серии шли к одному провайдеру |
| Claude (Anthropic) | Явный `cache_control` | Ставит точки на первый и последний системный блок через Polza/OpenRouter; остальная история не меняется |
| OpenAI, Gemini, Grok | Автоматический | Стабильный префикс; на Polza — тот же ключ серии |
| Неизвестная модель | Без разметки контента | На Polza отправляется только ключ серии; `cache_control` не ставится, чтобы незнакомый формат не превратился в 400 |

Что важно знать:

- **Первый шаг нового разговора обычно с нулём.** Кэш строится после первого запроса; попадание
  появляется на втором и следующих шагах. В продолжении уже прогретого разговора первый шаг
  тоже может попасть в кэш. Ноль на старте — норма, а не ошибка настройки.
- **Ключ серии — хэш, а не идентификатор.** `prompt_cache_key` собирается из проекта, разговора и
  модели через SHA-256 и не содержит их в открытом виде. Один разговор и одна модель дают один
  ключ на всех шагах, поэтому балансировщик Polza не уводит соседний шаг к провайдеру без кэша.
- **Заметки не переписывают прошлое.** `note.remember` дописывает в конец только новую строку, а
  не заменяет старый системный блок и не повторяет весь список: замена обнулила бы кэш истории,
  а полный список раздувал бы конец промпта. Актуальная запись всегда последняя, поэтому модель
  не путается.
- **Сокращение контекста может сбросить кэш.** Когда история не помещается в бюджет, старые
  сообщения выбрасываются или сокращаются — новый префикс отличается от прошлого. Это неизбежная
  плата за то, что запрос вообще помещается в лимит; после сокращения кэш строится заново.
- **`cached_tokens` видны в биллинге.** В `usage.prompt_tokens_details.cached_tokens` Polza
  расшифровывает, сколько входа прочитано из кэша; официальный DeepSeek отдаёт
  `prompt_cache_hit_tokens`, Anthropic-совместимые шлюзы — `cache_read_input_tokens`. Все три
  формы разбираются и пишутся в `model_usage.cached_prompt_tokens`. На экране «Последний прогон»
  появляется строка «Из кэша»; в логе сервера — `[cache] <модель>: из кэша N из M (X%)`, а при
  записи нового кэша добавляется `, записано в кэш K`.
- **Кэш не уменьшает кредиты тарифа.** `cached_tokens` уже входят в `prompt_tokens`, а кредиты
  считаются по полному входу. Провайдер выставляет за кэш меньшую ставку, но внутренняя оценка
  `PLATFORM_AI_PRICE_*` остаётся верхней границей по полной ставке входа — это честнее, чем
  показывать недоказанную скидку в финансовой статистике.
- **Смена модели начинает новую серию.** В ключе участвует модель: при переключении DeepSeek на
  Claude или другой ID кэш предыдущей модели не используется, и это ожидаемо.

Проверка на живом запросе: после второго шага в логе сервера должна появиться строка `[cache]` с
ненулевым `из кэша`, а в `GET /api/billing` — `cost.cachedPromptTokens > 0`. Если там ноль, проверьте,
что Base URL указывает на Polza.ai, модель начинается с `deepseek/`, а запуск сделал больше одного
шага.

## Подключение Cloudflare Workers AI

Этот раздел — про **разговор** с моделью: Workers AI отдаёт OpenAI-совместимый `/chat/completions`,
поэтому отдельный код не нужен, а адрес, модель и ключ — обычные `PLATFORM_AI_*`. Картинки для
проектов настраиваются отдельно — `PLATFORM_IMAGE_*`, раздел «Генерация изображений для проектов».

1. Откройте панель Cloudflare → **Workers & Pages** и скопируйте **Account ID**. Это не секрет,
   он входит в Base URL.
2. Создайте токен: **My Profile → API Tokens → Create Token**, право **Workers AI: Read**. Для
   запуска моделей достаточно Read; Edit нужен только для управления аккаунтом.
3. Выберите модель. Агенту нужны вызов инструментов и контекст не меньше
   `AGENT_CONTEXT_TOKENS_FREE` (по умолчанию 120 000), поэтому подходит `@cf/openai/gpt-oss-120b`: 128 000 токенов,
   function calling, reasoning low/medium/high. `@cf/meta/llama-3.3-70b-instruct-fp8-fast` тоже
   умеет tools, но видит только 24 000 токенов — история агента будет упираться в этот лимит.
4. Задайте переменные. Бесплатная модель тарифа «Старт»:

```dotenv
PLATFORM_AI_FREE_PROVIDER=Cloudflare Workers AI
PLATFORM_AI_FREE_BASE_URL=https://api.cloudflare.com/client/v4/accounts/<ACCOUNT_ID>/ai/v1
PLATFORM_AI_FREE_MODEL=@cf/openai/gpt-oss-120b
PLATFORM_AI_FREE_KEY_1=<API token>
```

Если Cloudflare должен стать основной моделью платных тарифов, те же значения — в `PLATFORM_AI_*`
(`PLATFORM_AI_PROVIDER`, `PLATFORM_AI_BASE_URL`, `PLATFORM_AI_MODEL`, `PLATFORM_AI_API_KEY`).
Бесплатная цепочка при этом может остаться на Agnes или тоже смотреть на Cloudflare; её резервом
служит настроенная модель платформы.

В GitHub Actions адрес, модель и имя провайдера — **Variables**, токен — **Secrets**:
`PLATFORM_AI_FREE_BASE_URL`, `PLATFORM_AI_FREE_MODEL`, `PLATFORM_AI_FREE_PROVIDER` и
`PLATFORM_AI_FREE_KEY_1` (или `PLATFORM_AI_BASE_URL`, `PLATFORM_AI_MODEL`,
`PLATFORM_AI_PROVIDER` и `PLATFORM_AI_API_KEY` для основной модели).

## Размер контекста и лимит модели

Модель получает всю переписку и весь вывод инструментов целиком, поэтому размер промпта — не
случайность, а настройка. За неё отвечает один модуль: `server/src/agent/context-budget.ts`.

У провайдера **два независимых лимита**, и ограничивать один из них — ошибка, которую мы уже
сделали дважды:

- **размер** — сколько токенов уходит в запросе (провайдер отвечает `ContextWindowExceededError`);
- **число сообщений** — сколько записей в массиве `messages` он принимает. Шлюз, с которым работает
  платформа, проверяет тело запроса и отвечает
  `[{"origin":"array","code":"too_big","maximum":100,"path":["messages"]}]`: сто сообщений по
  десять символов весят немного и всё равно отклоняются, потому что шаг агента добавляет два
  сообщения (ответ с вызовом инструмента и его результат) плюс проверка на каждое изменение — сорок
  шагов перешагивают сотню сами по себе.

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `AGENT_CONTEXT_TOKENS_PAID` | `150000` | Бюджет промпта платной модели; с резервом 8192 это 141 808 токенов |
| `AGENT_CONTEXT_TOKENS_FREE` | `120000` | Бюджет бесплатной цепочки: её резервные модели могут видеть только 128k |
| `AGENT_CONTEXT_TOKENS` | — | Общий fallback/потолок, если задан в окружении; отдельная настройка тарифа важнее |
| `AGENT_CONTEXT_OUTPUT_RESERVE` | `8192` | Место, оставленное на ответ; вычитается из бюджета |
| `AGENT_CONTEXT_MAX_MESSAGES_PAID` | `80` | Сколько сообщений может быть в запросе платной модели |
| `AGENT_CONTEXT_MAX_MESSAGES_FREE` | `80` | То же для бесплатной цепочки: ниже 8 значение не опускается |
| `AGENT_CONTEXT_MAX_MESSAGES` | `—` | Общий fallback, если задан; отдельная настройка тарифа важнее |
| `AGENT_MAX_STEPS` | `20` | Размер одного окна шагов |
| `AGENT_MAX_STEP_WINDOWS` | `2` | Сколько окон разрешено пройти без остановки; по умолчанию 20 × 2 = 40 шагов |

Двадцатый шаг больше не является ошибкой: после первого окна запуск продолжается в том же
разговоре, в прогресса просто появляется `21/40`. Остановка с кнопкой «Продолжить» случается
только на общем пределе — по умолчанию на 40-м шаге, и её можно отодвинуть через
`AGENT_MAX_STEP_WINDOWS` (не больше пяти окон, общий потолок — 100 шагов).

Что происходит внутри запуска:

- **Модель получает сохранённую переписку, а не копию из браузера.** Маршрут запуска читает сессию
  один раз и передаёт её в `AgentRunRequest.history`, а панель отправляет только реплики
  пользователя — их сервер сравнивает с сессией и дописывает то, чего в ней ещё нет. Это даёт
  разговору то, что браузер прислать не может: результаты инструментов прошлых запусков и ответы,
  которые пользователь никогда не отправлял заново. Из сохранённой истории перед отправкой уходит
  только то, что провайдер принять не может: `reasoning` не возвращается модели, а незакрытая пара
  «вызов без результата» и «результат без вызова» вырезается (об прерывании говорит отдельная
  заметка о продолжении);
- **Перед каждым шагом** история подрезается до бюджета, самым дешёвым изменением сначала: длинное
  сообщение пользователя (вставленный файл — это норма) сокращается по краям, у старых ответов,
  выводов инструментов и **аргументов вызовов** остаётся начало и конец, и только потом выбрасываются
  самые старые пары «вызов + результат» целиком (иначе провайдер отклонит запрос).
  Пользовательские и системные сообщения не выбрасываются никогда;
- **аргументы вызова тоже подрезаются**: `fs.write` приезжает с целым файлом внутри, а аргументы
  всех прошлых шагов уезжают в каждом запросе — обрезается всё, кроме `id` и имени, а обрезанные
  аргументы остаются валидным JSON-объектом с пометкой и началом значения, поэтому вызов остаётся
  в паре со своим результатом;
- **вырезанное заменяется дайджестом, а не теряется молча**: в системной заметке на месте обреза
  остаётся первая просьба пользователя (она задаёт проект), новые просьбы, выводы агента, список
  тронутых файлов и команд и прямая строка о том, что вывод инструментов выброшен и его надо
  получить заново. Заметка не растёт бесконечно: у каждого списка свой предел;
- **число сообщений ограничено отдельно**: когда вышел не размер, а длина запроса, старые шаги
  уходят целиком, а старые сообщения пользователя сворачиваются в ту же заметку — в ней
  остаётся начало каждой просьбы, а текущая задача остаётся целиком;
- **отказ провайдера по числу сообщений лечится так же, как по размеру**: из тела ответа читается
  названный предел (он берётся с запасом в 4 сообщения) или свой предел делится пополам, история
  сокращается ещё раз, и шаг повторяется один раз. Уменьшенный предел остаётся на весь запуск,
  чтобы следующий шаг не наткнулся на тот же отказ;
- **вывод инструмента ограничен при добавлении в историю**: журнал сборки — 6 КБ, файл — 24 КБ
  (а `fs.read` читает файл окнами по 20 000 символов и сам говорит, откуда продолжить);
- **схемы инструментов входят в бюджет**: они уезжают с каждым запросом, и не считать их —
  верный способ превысить лимит модели;
- **оценка калибруется по отчёту провайдера**: после каждого шага берётся реальное число
  `prompt_tokens` и отношение «символы на токен» пересчитывается;
- **отказ провайдера по размеру контекста — не конец запуска**: бюджет уменьшается вдвое, история
  подрезается ещё раз и шаг повторяется ровно один раз. Если провайдер отказал и на второй раз,
  запуск останавливается с числами в сообщении («N токенов при лимите M» или «отказался принять
  запрос из N сообщений: его предел — M») и советом начать новый диалог — это лучше, чем сырое тело
  ответа.

Чего это стоит в хранилище: запуск дописывает ходы по мере работы, поэтому ограничение стоит в
самой записи, а не в чтении. В сессии сохраняется читаемая копия, а не журнал: вывод инструмента —
до 8 000 символов, размышление — до 4 000, шаг не переписывает сессию целиком (в YDB — одна вставка
строки сообщения и строки с `updated_at`, без чтения всей переписки, в JSON-режиме иначе нельзя:
сессия там лежит одним файлом).

Где это видно:

- `/api/health` → `activity.context.paid` и `activity.context.free` — лимиты контекста по тарифам,
  `activity.context.steps` — общий предел шагов запуска;
- `/api/health` → `activity.runs` — сколько прогонов идёт, как раньше;
- лог старта сервера: `[agent] бюджет контекста на шаг: …`;
- контейнер размышления текущего ответа (он стоит **над** ответом): шаг, занятый контекст и время —
  цифры приходят в событии `run.progress` (`tokens`, `budget`). Если модель размышлений не присылает,
  вместо контейнера видна одна живая строка «Готовит ответ…» с теми же цифрами: пустого окна с
  обещанием в интерфейсе нет;
- серверный лог, если размышлений нет, а хочется понять почему: при `AI_STREAM_DEBUG=1` первые
  чанки каждого потока пишут имена полей `delta` (только имена, не текст) — видно, под каким полем
  шлюз прячет цепочку рассуждений. Разбор понимает `reasoning_content`, `reasoning`,
  `reasoning_details`, `reasoning_text`, `thinking` и `thought` — строкой, объектом или массивом
  частей, и в чанке ответа (`choices[0].message`), и в дельте потока (`choices[0].delta`).

### Размышления модели просят явно

Шлюзы отдают цепочку рассуждений только по просьбе: один и тот же адрес без `reasoning_effort`
присылает ответ и молчит о мыслях, а с ним — стримит их отдельным полем. Поэтому сервер просит
`reasoning_effort` по умолчанию (`WEBNESTDEV_AI_REASONING`, по умолчанию `medium`), а шлюз,
который такого поля не знает и отвечает `400`/`422`, получает **тот же запрос без просьбы** — запуск
не падает, а адрес запоминается на процесс, чтобы следующие шаги не платили за отказ двумя
запросами каждый. Размышление никогда не возвращается модели и хранится в сессии урезанным до
4 000 символов (`MAX_STORED_REASONING_CHARS`) на один ответ.

В панели размышление — контейнер **над** ответом: пока модель думает, он развёрнут и шапка
подписана «Размышляю…» с шагом, контекстом и временем; одним нажатием он сворачивается и
разворачивается обратно, а свёрнутый показывает последнюю строку мыслей, поэтому скрытый контейнер
не означает «перестало быть видно, что агент работает».

## Ошибки провайдера

Ответ провайдера разбирается в `server/src/provider/provider-errors.ts` и превращается в код, а не
в строку с JSON:

| Код | Когда |
| --- | --- |
| `CONTEXT_OVERFLOW` | 400/413 и упоминание контекста в теле — бюджет сокращается вдвое, шаг повторяется |
| `TOO_MANY_MESSAGES` | 400 и отказ валидатора по длине массива `messages` (`too_big`, «at most N items») — предел сообщений уменьшается, шаг повторяется |
| `AUTH` | 401/403 — ключ отклонён |
| `RATE_LIMIT` | 429 — слишком часто |
| `UNAVAILABLE` | 5xx — сбой на стороне провайдера |
| `BAD_REQUEST` | остальные 4xx — формат запроса |

Сообщение об ошибке пишется по-русски и содержит действие, а исходный текст провайдера остаётся в
`detail` (до 500 символов) для лога. Панель агента показывает `code` в событии `run.failed` и
объясняет именно эту причину.

## Кредиты и стоимость моделей

Пользовательский лимит платного тарифа — не сырые токены, а **кредиты**. Кредит нормализует
разные цены моделей: 5 000 кредитов «Плюса» — это примерно 50 млн токенов NestDev при обычной
смеси 90 % входа и 10 % выхода, но только около 10 млн токенов Max или 100 млн Mini. Поэтому
дорогая модель не съедает маржу тарифа, а пользователь видит один понятный бюджет.

```text
credits = ceil(
  prompt_tokens / 1 000 000 × input_credits_per_million
  + completion_tokens / 1 000 000 × output_credits_per_million
)
credits = max(credits, minimum_credits_per_run)
```

`reasoning`-токены входят в выход: провайдер тарифицирует их как completion. Минимум за запуск
покрывает короткие задачи, округление — вверх до целого кредита.

| Модель | Вход, кредитов за 1M | Выход, кредитов за 1M | Минимум за запуск |
|---|---:|---:|---:|
| NestDev (основная) | 50 | 510 | 1 |
| NestDev Max | 250 | 2 550 | 2 |
| NestDev Mini | 25 | 255 | 1 |

Это стартовые ставки, а не жёстко зашитая цена провайдера. У основной модели они меняются
переменными `PLATFORM_AI_CREDITS_INPUT_PER_MILLION`, `..._OUTPUT_PER_MILLION` и
`..._MINIMUM_PER_RUN` или полем `creditRates` в `POST /api/admin/ai`; значение из админки важнее
окружения. У Max/Mini — полем `creditRates` в каталоге (`/api/admin/ai/models`, раздел 7.13
[ADMIN_API.md](ADMIN_API.md)). Если поставить дорогую модель с ценой основной, кредиты будут
списываться слишком медленно и тариф уйдёт в минус.

`model_usage` хранит `model_id` и точное число `credits` за запуск. `getCreditBudget` суммирует их
за календарный месяц; строки до кредитного учёта оцениваются как 10 000 токенов = 1 кредит, а
запуски бесплатной Air не превращаются в кредиты. На бесплатном тарифе лимит кредитов равен нулю
и работает дневной лимит запусков; на платных тарифах дневного лимита нет — расход ограничивают
кредиты. Неизрасходованные кредиты тарифа не переносятся, но докупленные пакеты хранятся в
отдельном журнале `credit_ledger`, не сгорают и расходуются после месячного лимита. Свой
AI-провайдер проекта не тратит кредиты платформы.

## Учёт расхода

Каждый прогон агента записывает токены (вход/выход, а также сколько входа прочитано из кэша) в
таблицу `model_usage` (Postgres) или `.webnestdev/account/costs/<дата>.json` (JSON-режим). В той
же строке лежат `model_id` и списанные `credits`; бюджет тарифа читает именно их, а токены
остаются сырой аналитикой. В настройках аккаунта, в разделе «Тариф и подписка», виден расход за
сегодня: прогоны, токены, доля кэша, оценка стоимости и последний прогон — этого достаточно,
чтобы измерить, сколько стоит «лёгкий сайт» и насколько помогает кэш.

Для решений о цене подписки одной дневной оценки мало: нужна разбивка по моделям, тарифам и
месячная перспектива. Её отдают `GET /api/admin/stats/costs` и `/api/admin/stats/economics` —
контракт, формулы и переменные цен (`PLATFORM_AI_MODEL_PRICES`, `PLATFORM_INFRA_COST_PER_MONTH`)
описаны в [ADMIN_API.md](ADMIN_API.md), разделы 7.2–7.4. Запуски бесплатной модели записываются
как `free-model` и считаются нулевыми; если сработал платный резерв, фактическая стоимость выше —
админка предупреждает об этой границе явно.

Если провайдер присылает usage в стриме (поле `usage` в SSE), токены точные; иначе они
оцениваются по объёму текста, и такие записи помечаются как «оценка по объёму».

## Приоритет и безопасность

- Приоритет: свой провайдер проекта (его ключ и модель) всегда первый. Без него: на бесплатном
  тарифе — `NestDev Air` (Agnes, до трёх ключей) с резервом на модель платформы; на платном —
  выбранная модель платформы (`NestDev`, `NestDev Max` или `NestDev Mini`). `model` из запроса —
  это id каталога, а не upstream-имя; сервер проверяет его по тарифу.
- Провайдеры не смешиваются: ключ платформы никогда не отправляется на произвольный
  baseUrl проекта и наоборот.
- Платформенный доступ учитывается внутренними кредитами (`account/usage-store.ts`,
  `account/credits.ts`); реальный внешний биллинг — задача Фазы 3 плана
  `docs/MASS_ADOPTION_PLAN.md`.
- **Дневная квота запусков относится только к встроенной модели платформы.** Провайдер проекта — это
  ключ и модель пользователя: платформа за такой запуск не платит, поэтому запуск не считается и не
  блокируется, а на бесплатном тарифе запуски встроенной модели остаются с лимитом 10 в день.
  На платных тарифах дневной квоты нет — расход ограничивают кредиты. Решает это
  `consumeAgentRun(userId, { ownProvider })` в `account/usage-store.ts`:
  маршрут запуска (`routes/agent-ws.ts`) один раз спрашивает `getProjectProvider(projectId)` и
  передаёт ответ — проект со своим ключом получает снимок использования без списания квоты.
