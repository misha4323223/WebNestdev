# WebNestdev — поэтапный план до массового продукта

Статус: рабочий документ. Основан на аудите кода (октябрь 2026) и исследовании конкурентов
(Lovable, Bolt.new, Replit Agent, v0) за 2025–2026. Заменяет устаревшие
`DEVELOPMENT_PLAN.md` и `DEVELOPMENT_ROADMAP.md` как главный план; те документы
синхронизируются в Фазе 0.

## Рамка: что значит «лучший для массы»

«100% лучший» — не обещание, а критерий: план считается оптимальным, если порядок фаз
следует за узким местом, каждая фаза имеет измеримый выход и провал проверки возвращает
нас в начало фазы, а не в конец проекта.

- Целевой пользователь: человек без технического опыта (создатель, малый бизнес, студент,
  инди-разработчик), который хочет получить работающее веб-приложение из описания и
  показать его по ссылке.
- North Star: **доля новых пользователей, доведших задачу до работающего результата
  в первой сессии** (activation).
- Guardrail-метрики: P50/P95 времени до первого превью, доля задач, закрытых без ручной
  правки, стоимость на активированного пользователя, D7/D30 retention, доля обращений
  «непонятно, за что списали».
- Правило порядка: сначала ядро физически работает (Ф0), потом активация (Ф1), потом
  полнота продукта (Ф2), потом деньги (Ф3), потом масштаб (Ф4), потом рост (Ф5).
  Каждый этап разблокирует следующий; строить следующий поверх сломанного запрещено.

Почему такой порядок: нельзя активировать массу без работающего превью (Ф0); нельзя
удержать без «довёл до ссылки» (Ф1–Ф2); нельзя брать деньги без предсказуемых кредитов
(Ф3); нельзя обслужить тысячи без изоляции и лимитов (Ф4).

## Фаза 0 — «Фундамент доверия»

Цель: ядро физически работает у первого же пользователя; закрыты все P0 из аудита.

Работы:
- Symlink-escape: применить `resolveInsideSandbox`/`assertRegularFile` из
  `server/src/sandbox/path-guard.ts` в `tools/filesystem-tools.ts` и `tools/project-tools.ts`
  (сейчас там только лексическая проверка); для записи по несуществующему пути проверять
  реальный родительский каталог; тесты «симлинк внутри sandbox не выпускает наружу».
- Встроенный Preview: убрать `X-Frame-Options: DENY` для прокси-превью (оставить
  `frame-ancestors 'self'`), решить проблему абсолютных путей ассетов через прокси
  (rewrite base, отдельный origin/поддомен на проект или отказ от iframe); e2e-проверка,
  что iframe реально показывает приложение.
- Протокол авто-верификации (`agent-runtime.ts`): добавлять `assistant.tool_calls` перед
  tool-результатами build/preview/verify/browser; не отправлять скриншоты и большие
  бинарные данные в контекст модели (суммировать диагностику).
- Docker-топология (проверить и исправить на живом рантайме): достижимость Preview из
  серверного контейнера (container IP vs опубликованный порт), права UID 1000 на
  bind-mount, сироты preview-контейнеров после рестарта (reaper).
- Пользовательские мелочи: `HomeScreen.start()` без catch при 403 «лимит проектов»;
  понятный экран лимита вместо цикла «Повторить»; авторизация для `/api/tools` и
  `/api/sandbox/status`; `provider/stream-lines.ts` не падает на non-data строках SSE.
- Гигиена: удалить мёртвый дубликат реестра (`tools/tool-store.ts`,
  `tools/tool-registry.ts`, `tools/tool-definitions.ts`); синхронизировать доки
  (`RUNNING.md` — корневой Dockerfile vs `server/Dockerfile`); убрать неиспользуемые
  `AI_*` из `.env.example`; CI обязателен: типы + тесты + сборка.

Exit-критерии:
- Сценарий «новый аккаунт → описание → агент собрал проект → превью видно в UI →
  browser-проверка зелёная» проходит по чек-листу на чистой среде, прогон зафиксирован.
- 0 известных P0; CI зелёный (типы, тесты, сборка).

## Фаза 1 — «Магия за 5 минут» (активация)

Цель: новичок без ключей и настройки получает работающее приложение в первую сессию.

Работы:
- Встроенный доступ к модели по умолчанию: платформенный ключ/провайдер с учётом
  токенов; BYO-ключ остаётся опцией для продвинутых. Основа готова (`PLATFORM_AI_*`,
  `docs/PLATFORM_AI.md`, учёт токенов и cost-снимок в `/api/billing`); осталось —
  онбординг и кредитная экономика.
- Онбординг от идеи: стартовые шаблоны (лендинг, SaaS, магазин, дашборд уже есть в
  `HomeScreen`) как первый экран; настройка провайдера уходит из критического пути.
- Видимость работы агента: UI уже получает `tool.started/finished`, но игнорирует их —
  лента действий, статусы, тайминги, кнопка «Стоп».
- Честные ошибки: человеческий текст + следующее действие; повтор после сбоя;
  прогресс сохраняется.
- Надёжность цикла: кэш зависимостей (npm install не с нуля), стабилизация времени
  запуска Preview, повторы, лимиты шагов.
- Учёт стоимости: расширить `account/usage-store.ts` с «прогонов» до токенов/кредитов
  по категориям (build/chat/browser/hosting) — фундамент Фазы 3.

Exit-критерии (baseline замеряется в начале фазы):
- Activation ≥ согласованного порога (ориентир 40–50% новых пользователей).
- P50 времени до первого рабочего превью ≤ 3–5 минут.
- Стоимость на активированного пользователя известна и укладывается в unit-экономику.
- Встроенный режим работает без единого действия «вставь API-ключ».

## Фаза 2 — «Продукт, который не страшно оставить»

Цель: довести путь до «опубликовал ссылку и вернулся позже».

Работы:
- Публикация в один клик с готовым URL через российские облака (Yandex Cloud, VK Cloud
  и аналоги); явное различие «превью ≠ опубликовано», статус публикации и кнопка
  обновления (как у Lovable/Bolt/v0). Интеграции облаков — часть платной подписки.
- Автосохранение и откат версий/чекпоинты без знания Git; история проекта.
- Управление проектами и сессиями в UI: списки проектов и чатов и удаление проектов
  уже есть (кнопка «Чаты» в рабочей области, последняя сессия восстанавливается при
  открытии проекта, `GET /api/projects/:id/conversations` отдаёт лёгкие карточки);
  остались переименование и удаление самих сессий.
- Экспорт кода и двусторонний GitHub-синк (импорт уже реализован).
- Восстановление после инцидентов: бэкапы, регламент возврата кредитов за сбойные
  периоды (практика Lovable после GitHub-инцидента).

Exit-критерии:
- Пользователь без поддержки проходит «идея → приложение → публичный URL → возврат
  позже → продолжение».
- Проверено восстановление из бэкапа; потеря работы при сбое сервиса исключена.

## Фаза 3 — «Понятные деньги»

Цель: монетизация, которую не боятся; расход предсказуем.

Работы:
- Реальные платежи: платные тарифы уже описаны и выбираются в интерфейсе, остаётся подключить оплату и включать выбранный тариф; бесплатный тариф с понятными кредитами;
  выбор платёжного провайдера — отдельным шагом при входе в фазу.
- Прозрачность: баланс, разбивка расхода по категориям, предупреждения до порога,
  пауза/остановка, оценка стоимости задачи заранее; неудачные шаги не списываются молча.
- Адаптивные лимиты на пользователя/workspace/IP; антиабьюз (у Replit — ограничения
  исходящих соединений и запрет майнинга; у Lovable — логическая изоляция и WAF).

Exit-критерии:
- Апгрейд и отмена без модератора; unit-экономика положительна на платных.
- Обращения «непонятно, за что списали» стремятся к нулю.

## Фаза 4 — «Масштаб: тысячи пользователей»

Цель: надёжно обслуживать массу, безопасно исполнять чужой код.

Работы:
- YDB везде в проде; снять ограничение JSON-режима «один процесс» (сейчас квоты и
  проекты в JSON сериализуются только внутри процесса); мультиреплика.
- Sandbox: уйти от docker.sock на сервере к выделенным воркерам/runner-пулу с
  изоляцией уровня microVM (ориентир — Vercel Sandbox/Firecracker); ресурсные квоты
  на пользователя; отсутствие общего исполнения.
- Наблюдаемость: метрики, трейсы, алерты, runbook инцидентов, бэкапы/восстановление.
- Антиабьюз и защита: per-user/IP-лимиты, блокировка майнинга и скам-использования.

Exit-критерии:
- Целевая нагрузка (N одновременных агентских ран) без деградации, подтверждено
  нагрузочным прогоном.
- Изоляция подтверждена тестами; инцидент-учения проведены.

## Фаза 5 — «Рост и удержание»

Цель: пользователи возвращаются и приводят других.

Работы:
- Библиотека шаблонов и галерея примеров; шаринг превью и проектов.
- Коллаборация: роли, комментарии, совместные проекты.
- Интеграции в генерируемые приложения: CMS, аналитика, email, платежи.
- Локализация продукта, SEO/лендинг, реферальная механика.

Exit-критерии: D7/D30 retention растёт; есть органическая виральность через шаринг.

## Сквозные правила

1. Definition of Done у каждой фичи: тест + e2e-сценарий + метрика + обновлённые доки.
2. Никакой «фальшивой готовности»: фича не закрыта, пока не проверена через интерфейс
   пользователя.
3. Расширять продукт только на здоровом фундаменте предыдущих фаз.
4. Конец каждой фазы — ревью метрик и корректировка плана (план сам себя уточняет).

## Решения (зафиксировано)

1. Рынок: RU-первый. Интерфейс и материалы для русскоязычной аудитории.
2. Доступ к AI: модель платформы по умолчанию + свой ключ как опция. Основа в коде:
   `PLATFORM_AI_*` (см. `docs/PLATFORM_AI.md`) и учёт токенов/стоимости прогонов.
3. Бесплатный тариф: умеренный. Точные цифры калибруются после замера стоимости
   лёгкого сайта на реальной модели: владелец подключает модель и проверяет сам.
4. Публикация: российские облака (Yandex Cloud, VK Cloud и аналоги). Интеграции —
   часть платной подписки; публикация с готовым URL.

## Открытые вопросы (осталось)

- Размер бесплатных кредитов и правила списания — по факту замера стоимости лёгкого
  сайта и задач средней сложности.
- Конкретный облачный партнёр публикации и схема разделения затрат — на входе в Фазу 2.

## Anti-scope (не сейчас)

Коллаборация, маркетплейс шаблонов, мобильные приложения, экзотические провайдеры и
мультиязычность самого продукта — до Фазы 5.
