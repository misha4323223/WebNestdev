## Инженерные правила

1. Не считать действие выполненным только по намерению или сообщению модели.
2. После записи изменения перечитать изменённый файл и проверить SHA/коммит.
3. После изменения поведения запускать соответствующую проверку.
4. Ошибки инструментов должны возвращаться агенту с диагностикой, достаточной для исправления.
5. Не дублировать уже существующие инструменты — сначала проверять текущую архитектуру.
6. При каждом существенном изменении обновлять этот файл.

## История важных изменений

- В «Интеграциях» → «Сервисы» 20 российских сервисов (файлы S3, почта, оплата, AI, карты, CRM): ключ проверяется запросом провайдера до сохранения, хранится зашифрованным и переносится в переменные окружения проекта инструментами `service.status` / `service.env` / `service.secrets`.
- Агент видит подключённые облака через `cloud.status` и `cloud.request`: чтение и изменения (хосты ограничены провайдером, изменения — только по явной просьбе пользователя и при включённом переключателе в карточке).
- `domain.check` проверяет домены без ключей: WHOIS TCI для `.ru/.su/.рф`, RDAP для остальных зон; `unknown` не выдаётся за свободное имя.
- Коннекторы регистраторов (REG.RU, Beget, Timeweb Cloud) в «Интеграциях» → «Домены»: доступ проверяется чтением списка доменов, хранится зашифрованным и отдаётся агенту только через `domain.list` (только чтение).
- Анализ следующих интеграций и приоритеты (российские аналоги коннекторов Replit) зафиксированы в `docs/INTEGRATIONS_ROADMAP.md`.
- Смена ключа шифрования перешифровывает и подключения облаков, доменов и сервисов — в файловом хранилище (карты `провайдер → запись`) и в таблицах PostgreSQL; раньше эти записи остались бы на старом ключе.
- `c0a0e93a` — Preview дополнительно проверяет доступность HTTP-сервера внутри контейнера.
- `ec3828d2` — обновлена системная логика агента для цикла исправлений и повторной проверки.

## Ближайший конкретный результат

**Browser Tool должен позволить агенту открыть работающий Preview, получить результат страницы и использовать этот результат для следующего шага: обнаружить проблему → исправить → снова проверить.**
