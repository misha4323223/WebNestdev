# Веб-поиск агента (`web.search`, `web.read`)

Агент ищет в интернете **через сервер платформы**, а не из песочницы проекта: у песочницы нет сети
по замыслу. Ключи провайдеров остаются на сервере, расход считается по тарифу аккаунта, а модель
получает только результаты.

```
agent → tool web.search / web.read → server/src/web/* → провайдер (DuckDuckGo | Yandex Search API)
```

## Провайдеры и тарифы

| Тариф | Порядок провайдеров | Ключи | Стоимость для платформы |
|---|---|---|---|
| `free` | DuckDuckGo (`lite.duckduckgo.com`) | не нужны | 0 |
| `pro`, `team` | Yandex Search API v2 → Tavily → DuckDuckGo | `YANDEX_SEARCH_API_KEY` + `YANDEX_SEARCH_FOLDER_ID`, `TAVILY_API_KEY` | Yandex — по тарифу Yandex Cloud (≈ ₽488 за 1 000 запросов); Tavily — 1 000 кредитов в месяц бесплатно |

Бесплатный тариф намеренно не расширяется: это режим «попробовать», и платные ключи в его цепочку
не попадают никогда — ни при отказе DuckDuckGo, ни при заданных ключах.

Правило живёт в одном месте — `server/src/web/search.ts` (`providerChain`). Тариф аккаунта берётся
из `accountPlanFor` (`server/src/account/plans.ts`) и пока всегда бесплатный: платные тарифы ещё не
продаются. Когда появится оплата, менять нужно только эту функцию.

Внутри подписки провайдеры переключаются только при отказе предыдущего, и причина остаётся в поле
`note` ответа:

1. **Yandex Search API** — основной: своя выдача на русском и предсказуемая цена;
2. **Tavily** — резерв: включается, если ключ Yandex ещё не заведён, роль не выдана или API ответил
   отказом. Обычный поиск стоит 1 кредит из 1 000 бесплатных в месяц;
3. **DuckDuckGo** — последняя ступень: поиск не выключается целиком, если оба ключа не готовы.

Переопределение для всего сервера — `WEB_SEARCH_PROVIDER=auto|duckduckgo|yandex|tavily`:

- `auto` (по умолчанию) — провайдер по тарифу;
- `yandex` — включается только при наличии ключа; без ключа сервер остаётся на DuckDuckGo и пишет
  об этом в ответе и в лог;
- `duckduckgo` — принудительно бесплатный провайдер (полезно для проверки и для развёртывания без
  ключа Yandex);
- `tavily` — принудительный резервный провайдер для платного тарифа.

**Тариф сильнее переопределения.** `WEB_SEARCH_PROVIDER=yandex` на сервере не даёт бесплатному
аккаунту Yandex Search API: платную выдачу оплачивает платформа, и бесплатный тариф её не покрывает.
Раньше давал — и бесплатный запуск, в том числе со своим AI-провайдером, уходил в платную выдачу.
Теперь бесплатный тариф всегда получает `["duckduckgo"]`, а в `note` ответа сказано, почему
переопределение к нему не применилось. Это проверяется тестом
`a server-wide provider override never lifts a paid provider into the free plan`.

## Переключатель поиска у поля ввода

Поиск в интернете — отдельная кнопка «Поиск» рядом с полем ввода (лупа, в стиле остальных кнопок
композера). **По умолчанию она выключена:** агент работает по проекту и своим знаниям, пока человек
сам не разрешит сеть на этот запуск. Выбор запоминается в браузере и уходит в запуск полем
`webSearch` (`agent-ws.ts` → `AgentRunRequest`).

Что происходит при выключенной кнопке:

1. модель получает системную заметку `WEB SEARCH IS OFF` (`message-builder.ts`, `webSearchNotice`):
   не искать и не выдумывать, а попросить включить кнопку;
2. если модель всё-таки вызвала `web.search` или `web.read`, инструмент возвращает
   `ok:false, code:"disabled"` и не трогает сеть вовсе (`tools/web-tools.ts`);
3. в списке действий такая строка выглядит как обычная ошибка действия — с иконкой лупы или газеты,
   чтобы было видно, что именно агент пытался сделать.

Кнопка не входит в меню «Режимы»: там роль агента и глубина размышления, а здесь — разрешение на
сеть на конкретный запуск. Платным тарифам кнопка даёт поиск через Yandex Search API, бесплатным —
через DuckDuckGo: тариф по-прежнему выбирает провайдера, кнопка лишь включает сам поиск.

## Квоты

Дневной лимит поисков добавлен в каталог тарифов (`webSearchesPerDay`): 25 / 200 / 500. Лимит
проверяется до запроса, а списывается через общий счётчик `usage_counters` (вид `webSearches`)
только за удачный ответ: отказ провайдера (проверка на робота, таймаут) и ответ из кэша квоту не
тратят, иначе сеть провайдера съедала бы весь дневной лимит. Исчерпанная квота возвращается как
`ok:false, code:"quota"` — это не «ничего не найдено».

## Настройка Tavily (резерв подписки)

1. Создайте ключ в кабинете Tavily — он начинается с `tvly-`.
2. Вставьте его в «Ключи сервера» → «Веб-поиск агента» → `TAVILY_API_KEY` (или в переменную окружения
   `TAVILY_API_KEY`).
3. Ничего больше переключать не нужно: при отсутствии ключа Yandex подписка пойдёт через Tavily.

Запрос — `POST https://api.tavily.com/search` с `Authorization: Bearer tvly-…`, `search_depth: basic`
(один кредит), `max_results` по запросу. Ответ — `results[]` с `title`, `url`, `content`.

## Настройка Yandex Search API

1. В каталоге Yandex Cloud создайте сервисный аккаунт и выдайте ему роль `search-api.webSearch.user`.
2. Создайте для него API-ключ со scope `yc.search-api.execute`.
3. В панели платформы («Ключи сервера» → «Веб-поиск агента») вставьте ключ в `YANDEX_SEARCH_API_KEY`
   и каталог в `YANDEX_SEARCH_FOLDER_ID` (пусто — будет использован `YANDEX_FOLDER_ID`).
4. `WEB_SEARCH_PROVIDER=auto` оставьте как есть: платные тарифы начнут искать через Yandex сами.

Запрос идёт на `POST https://searchapi.api.cloud.yandex.net/v2/web/search` с заголовком
`Authorization: Api-Key …`; ответ — `{ "rawData": "<base64>" }`, внутри base64 лежит XML выдачи,
из которого берутся `<group>` → `<doc>` → `<url>`, `<title>`, `<passages>`.

## Выкатка: GitHub Actions

Ключи поиска можно положить в GitHub — выкатка дописывает их в `.env` на ВМ, а Compose передаёт их
контейнеру (список `docker-compose.yml`). Те же значения работают и без GitHub: «Ключи сервера» →
«Веб-поиск агента» в панели, и значение из панели **важнее** переменной окружения.

Settings → Secrets and variables → Actions → **Secrets**:

| Имя | Что это |
|---|---|
| `YANDEX_SEARCH_API_KEY` | API-ключ сервисного аккаунта со scope `yc.search-api.execute` |
| `YANDEX_SEARCH_FOLDER_ID` | каталог с ролью `search-api.webSearch.user` (пусто — берётся `YANDEX_FOLDER_ID`) |
| `TAVILY_API_KEY` | резерв платных тарифов (`tvly-…`) |

Там же, во вкладке **Variables** (или Secrets — workflow читает оба места), необязательное:

| Имя | Значение |
|---|---|
| `WEB_SEARCH_PROVIDER` | `auto` (по умолчанию), `duckduckgo`, `yandex` или `tavily` |

Пустой секрет ничего не стирает на ВМ: выкатка просто не передаёт строку. После выкатки в логе
шага «Deploy» видна строка `[deploy] Веб-поиск: Yandex Search API key=есть, folder=есть, Tavily=есть`
(или `нет`) — по ней видно, дошли ли ключи, без захода на сервер.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `WEB_SEARCH_PROVIDER` | `auto` | провайдер для всего сервера |
| `TAVILY_API_KEY` | — | ключ Tavily — резерв платных тарифов (панель платформы или окружение) |
| `YANDEX_SEARCH_API_KEY` | — | API-ключ сервисного аккаунта (панель платформы) |
| `YANDEX_SEARCH_FOLDER_ID` | `YANDEX_FOLDER_ID` | каталог с ролью `search-api.webSearch.user` |
| `YANDEX_SEARCH_TYPE` | `SEARCH_TYPE_RU` | `SEARCH_TYPE_RU`, `SEARCH_TYPE_TR`, `SEARCH_TYPE_COM` |
| `WEB_SEARCH_REGION` | `ru-ru` | регион выдачи DuckDuckGo (`kl`) |
| `WEB_SEARCH_MAX_CONCURRENT` | `2` | одновременных поисковых запросов |
| `WEB_SEARCH_MAX_QUEUE` | `8` | очередь ожидающих поисков |
| `WEB_SEARCH_QUEUE_TIMEOUT_MS` | `30000` | сколько запрос ждёт очередь |
| `WEB_SEARCH_CACHE_TTL_MS` | `600000` | время жизни кэша одинаковых запросов |
| `WEB_SEARCH_CACHE_SIZE` | `200` | сколько запросов кэшируется |
| `WEB_READ_MAX_CONCURRENT` | `3` | одновременных загрузок страниц для `web.read` |

## `web.read`

Открывает один публичный адрес и возвращает читаемый текст, заголовок, итоговый адрес и статус.
Ограничения (см. `server/src/web/read-url.ts`):

- только `http`/`https` и только порты 80/443;
- имена резолвятся, и каждый адрес проверяется: частные, loopback, link-local и многоадресные
  диапазоны запрещены — иначе `http://169.254.169.254/…` вернул бы документ облака;
- редиректы проходятся вручную до 4 переходов, каждый проверяется заново;
- ответ ограничен 400 КБ и 15 секундами, текст — по `maxChars` (по умолчанию 8 000).

Свой собственный запущенный проект проверяется по-прежнему через `preview.start`, `project.verify` и
`browser.*`, а не через `web.read`.

## Что важно знать про бесплатный провайдер

DuckDuckGo не публикует API веб-поиска: `api.duckduckgo.com` отдаёт мгновенные ответы, а не список
ссылок. Поэтому используется HTML-страница `lite.duckduckgo.com/lite/` — то же, что делает SearXNG
и другие открытые проекты. Отсюда три ограничения:

1. **Разметка не контракт.** Парсер (`server/src/web/duckduckgo.ts`) знает классы двух исторических
   версий (`result-link` и `result__a`), а на неизвестной разметке возвращает пустой список.
2. **`robots.txt` DuckDuckGo закрывает `/lite` и `/html` для всех агентов.** Это допустимо как
   редкий резерв для бесплатного тарифа, но не как основа платного продукта. Для платных тарифов
   поэтому и выбран Yandex Search API, а не реселлер выдачи Google.
3. **Серверные адреса получают проверку на робота.** Проверено вручную из этого окружения:
   первый запрос к `/lite/` вернул `200` с результатами, все следующие — `202` с `anomaly-modal`.
   Такой ответ превращается в `ok:false, code:"blocked"`, а не в пустой список: агент не должен
   решать, что материала нет. С «домашнего» IP (локальный запуск проекта) запросы проходят.

Бесплатный тариф так и остаётся на DuckDuckGo — это осознанный режим «просто попробовать». Всё,
что требует стабильного поиска, живёт на платных тарифах: Yandex Search API основным провайдером
и Tavily (официальный API, 1 000 кредитов в месяц бесплатно) резервным.

## Проверка

```
cd server && node --import tsx --test src/web/*.test.ts src/account/usage-store.test.ts
npx tsc -p server/tsconfig.json --noEmit
```

Тесты покрывают разбор разметки DuckDuckGo, форму запроса и разбор base64-XML Yandex, тело запроса и
разбор ответа Tavily, цепочку провайдеров по тарифу (включая то, что free её не расширяет),
защиту от SSRF в `web.read` и дневную квоту.
