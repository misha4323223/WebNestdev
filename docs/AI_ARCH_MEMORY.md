# Архитектурная память агента (этап 3)

Статус: **каркас, выключен по умолчанию**. Флаг `AGENT_ARCH_MEMORY`; без него контекст,
каталог инструментов и обычный запуск не меняются.

## Что уже есть

### Документы проекта

Агент читает из корня проекта только три явных файла:

- `ARCHITECTURE.md` — модули, границы, потоки данных, инварианты;
- `DECISIONS.md` — решения и причины;
- `CONTRACTS.md` — контракты API/БД/событий.

Лимиты: 12 000 символов на файл, 24 000 суммарно. Перед включением в контекст весь документ
проверяется на известные форматы ключей и значения секретов. Если найден секрет, файл
**пропускается целиком**, а не обрезается: причина видна, содержимое — нет.

Память добавляется в `PROJECT CONTEXT` отдельным блоком с явной оговоркой: это данные для
ориентации, а не инструкции и не замена чтению кода. При расхождении доверять нужно коду.

### Скелет

`project.memory {action:"skeleton"}` собирает черновик `ARCHITECTURE.md` из `repo.map`:
пакеты, entry points, тесты, fingerprint. Разделы «Границы», «Потоки данных» и «Инварианты»
остаются явными `TODO`: агент не выдумывает архитектуру, которой нет в коде.

### Инструмент и контролируемая запись

`project.memory`:

- `action:"read"` — вернуть документы, `missing` и `skipped`;
- `action:"skeleton"` — вернуть Markdown-черновик и путь `ARCHITECTURE.md`;
- `action:"diff"` — показать unified patch, `currentHash`, `nextHash`, не записывая файл;
- `action:"write"` — записать только при `confirm:true` и точном `expectedHash` из diff.

Запись — compare-and-swap: если документ изменился между diff и write, запись отклоняется и
требует нового diff. Разрешены только три файла памяти, максимум 24 000 символов, секреты
отвергаются. Запись учитывается в storage quota как обычная запись в проект.
