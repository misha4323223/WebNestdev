# Задачи проекта

## Песочница

- [x] **Память по классу команды:** 25.11.2026, 21:26 UTC. Заведомо дешёвые читающие команды (`ls`, `cat`, `git status`, `grep`, `find`…) получают потолок 256 МБ (`SANDBOX_MEMORY_LIGHT_MB`, минимум 64), а сборки, установки, `node` и любое неизвестное — прежние `SANDBOX_MEMORY_MB` (1024 МБ). Резервация в общем бюджете и `--memory` контейнера берут одно и то же число; на удалённом runner потолок едет в `options.memoryMb`. Выключатель `SANDBOX_COMMAND_MEMORY_CLASS=0`; при заданном едином `SANDBOX_MEMORY` деление не применяется. Тесты: `server/src/sandbox/command-memory.test.ts`.
- [x] **Квота долгих заданий:** 25.11.2026, 21:26 UTC. `terminal.start` проверяет дневной лимит минут до запуска контейнера и списывает секунды жизни контейнера при завершении, остановке и таймауте (`server/src/sandbox/job-quota.ts`). Очереди аккаунта у заданий намеренно нет: фоновое задание не должно заставлять обычные команды того же аккаунта ждать своего конца. Тесты: `server/src/sandbox/job-quota.test.ts`.

## Preview

- [ ] **T2. Ускорение установки зависимостей (зеркало реестра + предустановленный слой):** сделано 2026-11-25: замер (`preview/install-metrics.ts`), слой (`preview/starter-layer.ts`), зеркало (`preview/npm-registry.ts`), скрипты `cache:stats` и `layer:build`. Дальше по этапам, после цифр с прода:
  - **Шаг 0 — замер:** смотреть медиану `cached: false` в `npm run cache:stats`. Меньше 10 с — ничего не менять.
  - **Шаг 1 — зеркало:** поднять зеркало реестра на каждой ноде (локальный диск, не Gluster), задать `WEBNESTDEV_NPM_REGISTRY` и разрешить его адрес в egress как прокси. Установка получает только `npm_config_registry`; недоступное зеркало ничего не ломает — код уже откатывается на публичный реестр. Работает для любых версий и для промтов без шаблона.
  - **Шаг 2 — слой:** `WEBNESTDEV_STARTER_KIT_DIR` (набор `package.json` + lock) и `WEBNESTDEV_STARTER_LAYER_DIR`, сборка `npm run layer:build -- --kit <каталог>`. Слой получает только проект, чьи `package.json` и lock совпали байт в байт; остальные идут обычным путём. Маркер кэша заполняется хэшем проекта, поэтому `npm install` не запускается вовсе.
  - **Тарифы:** установка нужна на всех тарифах (сборка статики — «Старт», функции — «Плюс», контейнерный предпросмотр — «Премиум»), поэтому оптимизация тарифно-нейтральна и не расширяет возможности плана. Проверять, что ограничения `entitlements.ts` не обходятся, при любых будущих правках.
  - **Не делать:** общий записываемый `node_modules` или `npm_config_cache` для всех песочниц (подмена пакетов между аккаунтами), симлинк на общий каталог, слой на Gluster, кэш реестра внутри egress-прокси (CONNECT без расшифровки).
  - **Открытый риск:** файлы слоя `0444` — если пакету нужно писать в свой файл в рантайме, проект получит `EACCES`; выключатель `WEBNESTDEV_STARTER_LAYER=0`.
